# bizmote オウンドメディア 運用手順書(非エンジニア向け)

このサイトは「記事を書いて、保存ボタンを押すと、数分後に自動で公開される」仕組みになっています。
プログラミングの知識は不要です。日常の運用はすべてブラウザだけで完結します。

---

## 1. 仕組みの全体像(1分で理解する)

```
Pages CMS(ブラウザの編集画面)
   ↓ 保存すると
GitHub(記事や設定のファイル置き場)
   ↓ 変更を検知して
Cloudflare Pages(自動でサイトを組み立てて公開)
   ↓ 数分後
https://bizmote.jp に反映
```

- **Pages CMS** … 記事を書く場所。ブラウザで使う無料のCMSです。
- **GitHub** … すべてのデータの保管庫。Pages CMSが裏で自動的に読み書きします。
- **Cloudflare Pages** … 公開サーバー。保存のたびに自動で最新のサイトを公開します。

## 2. Pages CMS の初期設定(最初の1回だけ)

1. https://app.pagescms.org/ を開く
2. **「Sign in with GitHub」** でログイン(このリポジトリ `daisukeyamaoka-bizmote/HP` にアクセスできるGitHubアカウントを使う)
3. リポジトリ一覧から **HP** を選ぶ
4. 左メニューに「記事」「お知らせ」「書き手(メンバー)」「サイト設定」が表示されれば設定完了です
   (この画面構成は、リポジトリ直下の `.pages.yml` というファイルで定義されています)

## 3. 記事の追加方法

1. Pages CMS を開き、左メニューの **「記事」** を選ぶ
2. 右上の **「Add Entry(追加)」** を押す
3. 各項目を入力する:

| 項目 | 書き方 |
|---|---|
| タイトル | 記事の見出し。そのままページの大見出しになります |
| スラッグ | URLになる半角英字。例:`enterprise-sales-blueprint`。**公開後は変えないでください**(URLが変わり、リンク切れになります) |
| リード文 | 一覧ページや検索結果に出る2〜3行の要約 |
| この記事の結論 | 記事冒頭の「この記事の結論」枠に表示される150〜200字。**AI検索に引用されやすくなる最重要項目なので必ず書く** |
| カテゴリ | GTM/AX/起業・事業づくり から選択 |
| 書き手 | 執筆したメンバーを選択 |
| 公開日 | 記事の日付 |
| 更新日 | 後から加筆したときに入れる(未入力でOK) |
| メイン画像 | 16:9の画像をアップロード(任意) |
| 下書き | **オンにすると公開されません**。書きかけはオンにしておく |
| 本文 | 記事本体。見出し(H2)を使って構成する |

4. 右上の **「Save(保存)」** を押す → 数分でサイトに反映されます

### 本文の書き方(見出し・太字・画像)

本文欄はリッチテキストエディタです。文字を選択すると出るツールバー、またはショートカットで指定します。

| やりたいこと | 操作 |
|---|---|
| 大見出し(H2) | ツールバーの「H2」/ 行頭に `## ` + スペース |
| 小見出し(H3) | ツールバーの「H3」/ 行頭に `### ` + スペース |
| 太字 | 文字を選択 → **B** ボタン / `Ctrl+B`(Mac: `Cmd+B`) |
| 箇条書き | リストボタン / 行頭に `- ` + スペース |
| リンク | 文字を選択 → リンクボタンでURLを入力 |
| 本文中に画像 | 挿入したい行にカーソルを置く → 画像ボタン → アップロード(何枚でも可) |

- **記事のH1(大見出し)は「タイトル」欄が自動的になります。本文中でH1は使わないでください**(見出し階層が壊れ、SEO・AI検索に悪影響)。本文の見出しはH2から使います
- 本文に入れた画像は `public/uploads/` に自動保存されます
- 記事冒頭の大きな画像は、本文ではなく **「メイン画像」欄**(16:9推奨)に入れます

## 3-2. 記事執筆ガイドライン(AI検索に引用されるための共通ルール)

### 大原則

AI検索(ChatGPT / Claude / Perplexity)は、記事全体を読んで要約するのではなく、**「そのまま引用できる自己完結した塊」を探して抜き出します**。したがって、人間向けの起承転結ではなく、**結論を先に置く**構成が有効です。

### 記事の標準構成(この順番で書く)

**① タイトル**
具体的に。「〜する方法」より「〜を3工程に分解する」のように中身が分かる形にし、読者が実際に検索する言葉を入れる。

**② 「この記事の結論」欄(最重要)**
150〜200字で記事全体の答えを完結させる。ここだけ読めば要点が分かる状態にする。AIが最初に拾いに来る項目なので、**空欄で公開しない**。

**③ 冒頭の段落 — 定義から入る(Definition Lead)**
冒頭150〜200字を次の構造で書く:

> 「[用語] は [カテゴリ] であり、[他と違う点] である」

例:「AX(AIトランスフォーメーション)とは、AIツールの導入ではなく、業務を分解して仕組みに置き換える取り組みである。」
AIは「◯◯とは何か」という質問に対し、この形の文を探して引用する。

**④ 本文 — H2見出し + 結論ファースト**
- H2で章立てする(本文でH1は使わない)
- **各H2の直後に、その章の結論を1〜2文**で書き、理由・詳細はその後に置く
- 見出しは「工程1:宛先の選定——『会いたい人』ではなく『動かせる人』」のように、見出しだけで内容が分かる具体名にする
- 1つの章につき論点は1つ。長くなったら章を分ける

**⑤ 数字・固有名詞・実例を入れる**
「多くの企業」ではなく「1社あたり2時間」「90日で1業務」。自社の現場で確かめた一次情報を書く。出典があるものは出典を明記する。

**⑥ 末尾に「よくある質問(FAQ)」**
Q&A形式はAIがそのまま回答として引用しやすい。3問程度でよい。
CMSの「FAQ」欄に入れると検索エンジン向けの構造化データ(FAQPage)が自動生成されるため、**本文末尾とFAQ欄の両方**に書く。

**⑦ 更新日を入れる**
加筆したら「更新日」を更新する。AI・検索エンジンともに新しい情報を優先する。

### 書き方の細かいルール

| ルール | 理由 |
|---|---|
| 1段落は3〜4文まで | 塊が小さいほど引用されやすい |
| 「これ」「それ」を多用しない | 抜き出されたときに意味が通らなくなる |
| 箇条書き・表を使う | 構造が明確でAIが解釈しやすい |
| 専門用語は初出時に説明する | その定義文自体が引用対象になる |
| 記事内に必ず1つ「持ち帰れる結論」を置く | 引用する価値のある主張になる |

### やってはいけないこと

- 本文でH1を使う(見出し階層が壊れる)
- 「この記事の結論」を空欄のまま公開する
- 結論を記事の最後まで引っ張る(AIが途中で拾えない)
- 公開後にスラッグ(URL)を変更する(リンク切れ・評価のリセット)

### 見本記事

`content/articles/legacy-ax-90days.md`(老舗企業のAX)が、このガイドラインを全て満たした見本です。迷ったらこの記事の構成を真似してください。

### サイト側で自動対応済みのもの(書き手が意識しなくてよいこと)

- Article構造化データ(著者・公開日・更新日)、著者のPerson構造化データ
- パンくずリストの構造化データ、全ページ固有のメタ情報
- `/llms.txt`(AI向けのサイト案内。記事を追加すると自動更新)
- AIクローラー(GPTBot / ClaudeBot / PerplexityBot 等)の明示許可

## 3-3. Claude に記事の作成を依頼する

記事はClaudeに書かせることもできます。Claude Code(このリポジトリを開いた状態)に、以下のテンプレートで依頼してください。ガイドラインに沿った原稿が `content/articles/` に直接作成され、そのままPages CMSでも編集できます。

### 依頼テンプレート(コピーして使う)

```
docs/運用手順書.md の「3-2. 記事執筆ガイドライン」に従って、新しい記事を1本書いてください。

- テーマ:(例:インサイドセールスの立ち上げで最初にやるべきこと)
- カテゴリ:(gtm / ax / startup のいずれか)
- 書き手:(daisuke-yamaoka / daiki-okui / hayato-sudo / yasuyuki-iwata / kyohei-watanabe のいずれか)
- 想定読者:(例:中堅企業の営業責任者)
- 必ず入れたい内容:
  -(例:自社で実際に検証した数字)
  -(例:よくある失敗パターン)
- 文字数の目安:2,000〜3,000字

content/articles/ に Markdown で作成し、公開日は今日、下書き(draft)は true にしてください。
```

### 依頼するときのコツ

- **テーマは具体的に**。「営業について」ではなく「大手企業の役員にアポを取る手順」のように絞る
- **一次情報(自社の実体験・数字・失敗談)を必ず伝える**。ここが記事の価値になり、AIにも評価される。Claudeは事実を創作できないため、渡した情報だけが具体例になる
- **最初は `draft: true`(下書き)で作らせる**。Pages CMSで内容を確認・修正してから、下書きをオフにして公開する
- **既存記事の更新も依頼できる**:「`content/articles/xxx.md` に最新の事例を追記して、更新日を今日にして」のように頼む

### 作成後にやること

1. Pages CMS の「記事」で下書きの記事を開く
2. 事実関係(数字・企業名・固有名詞)が正しいか**必ず人間が確認する**
3. 必要なら画像を差し込む(本文中の画像ボタン、メイン画像欄)
4. 「下書き」をオフにして保存 → 数分で公開

## 5. 公開の仕組みと確認方法

- **保存=公開依頼** です。保存すると自動でビルドが始まり、**約2〜3分**で反映されます
- 反映されたか確認するには、該当ページを開いて再読み込み(Ctrl+R / Cmd+R)
- 「下書き」をオンにして保存すれば、公開せずに保存だけできます
- 間違えて公開した場合は、記事を開いて「下書き」をオンにして保存すれば非公開に戻ります

## 6. 書き手(メンバー)の追加・変更

1. 左メニューの **「書き手(メンバー)」** で追加・編集できます

   自分で編集が難しければ、Claude Code に「.pages.yml の書き手の選択肢に◯◯(スラッグ:xxx)を追加して」と頼めば完了します

## 7. サービス名・会社文言の一括変更手順

サービス名(bizU／いつでも番頭さん／NANORIBA)や会社の文言は、**1箇所で管理**されているため、変更は1分で終わります。

### 手順(Pages CMS)

1. Pages CMS 左メニューの **「サイト設定」** を開く
2. 変更したい項目を書き換える
   - **起業家輩出コミュニティの名称**(NANORIBA):コミュニティ名を変える場合
   - **会社カテゴリー**(GTMコンサルティングファーム)
   - **タグライン**(運営元ページの大見出し)
   - **フッターの一文説明**
   - **カルチャーデックのURL**:入力するとフッターの「運営元」欄にリンクが出ます(空欄なら非表示)
3. 保存する

これだけで、以下のすべてが自動で切り替わります:

- 「運営元について」ページ(タグライン・サービス・会社概要の事業内容)
- 「サービス」ページ、フッターの「専門領域」
- AI検索向けの説明ファイル(llms.txt)や各ページのメタ情報

> bizU・いつでも番頭さん の名称自体を変える場合は `src/data/services.ts` の編集が必要です。Claude Code に「サービス名を◯◯に変えて」と依頼してください。

### 記事本文の中にサービス名を書いた場合

記事本文は自由テキストなので、本文中に旧名称がある記事は個別に直します。
GitHub の検索(リポジトリを開いて `t` キー→検索窓に旧名称)で該当ファイルを探すか、
Claude Code に「content/ 以下の旧サービス名『◯◯』を『△△』に一括置換して」と頼んでください。

## 8. ドメイン設定(bizmote.jp を新サイトに切り替える)

> **現状**:このリポジトリはすでに **Vercel** に接続されており、push のたびに自動デプロイされています(プレビューURLがPRに自動コメントされます)。Vercelのまま運用する場合は「8-A」、仕様書どおり Cloudflare Pages に載せ替える場合は「8-B」の手順に従ってください。どちらか一方でかまいません。

### 8-A. Vercel で bizmote.jp を公開する場合(現在の構成のまま・最短)

1. https://vercel.com/ にログイン → プロジェクト **hp** を開く
2. Settings → **Domains** → `bizmote.jp` を追加
3. 画面に表示される DNS 設定値(Aレコード または ネームサーバー)を、お名前.com の管理画面で設定する
   - お名前.com にログイン → 対象ドメイン → DNS設定 で、Vercel が指示するレコードを追加
4. 反映(数時間〜24時間)後、https://bizmote.jp が新サイトを表示すれば完了。SSL(https化)は自動です

### 8-B. Cloudflare Pages に載せ替える場合(仕様書どおりの構成)

現在のドメイン(bizmote.jp)は お名前.com で管理されています。切り替えは次の順で行います。

1. **Cloudflare Pages にプロジェクトを作成**
   - Cloudflare にログイン → Workers & Pages → Create → Pages → 「Connect to Git」
   - リポジトリ `daisukeyamaoka-bizmote/HP` を選択
   - 設定値:Production branch = `main`/Build command = `npm run build`/Build output directory = `dist`
   - デプロイ後、`xxxx.pages.dev` という仮URLで表示を確認する
2. **Cloudflare にドメインを追加**
   - Cloudflare の「Add a site」で `bizmote.jp` を登録(Freeプランで可)
   - Cloudflare からネームサーバー2つ(例:`xxx.ns.cloudflare.com`)が発行される
3. **お名前.com でネームサーバーを変更**
   - お名前.com にログイン → ドメイン設定 → ネームサーバー設定
   - Cloudflare から発行された2つに書き換える(反映まで数時間〜24時間)
4. **Cloudflare Pages にカスタムドメインを設定**
   - Pages プロジェクト → Custom domains → `bizmote.jp` を追加
   - SSL証明書(https化)は自動で発行されます
5. **切り替え完了の確認**
   - https://bizmote.jp が新サイトを表示すれば完了
   - 旧WordPressサーバーは1〜2週間様子を見てから解約する

> 補足:サイトのURLを変える場合(例:別ドメインにする)は、Pages CMS「サイト設定」の「サイトURL」も合わせて変更してください。

## 9. 画像・ロゴについて

- **記事の画像**:Pages CMS の画像アップロード欄から入れます(`public/uploads/` に保存されます)
- **メンバーの顔写真**:「書き手(メンバー)」の「顔写真」欄からアップロード(正方形推奨)

  `public/images/RGB_black.png`(ヘッダー用・黒の横ロゴ)/ `public/images/RGB_white.png`(フッター用・白の横ロゴ)/ `public/images/RGB_black_b.png`・`RGB_white_b.png`(「b」マーク)。ファビコン(`public/favicon.png`)とSNS画像(`public/ogp.png`)は「b」マーク・横ロゴから生成しています
- **SNSシェア画像(OGP)**:`public/ogp.png`(1200×630px)。差し替えは同名で上書き

## 10. デザインを変更したいとき

このサイトの見た目は **`docs/DESIGN_SPEC.md`(デザイン仕様書)** が正です。デザインを変えるときは次の流れで進めます。

```
① Claudeのデザイン機能で見た目を編集・確定
      ↓ 確定した仕様書(DESIGN_SPEC.md)や .dc.html を書き出す
② そのファイルを Claude Code に渡す
      ↓
③ Claude Code がサイト(Astro)に反映して push
      ↓
④ プレビューで確認 → 問題なければマージ(本番反映)
```

- **見た目・レイアウトの変更**(色、ヘッダー、セクション構成、新しい画面)→ デザイン機能で編集 → Claude Code に渡す
- **記事・お知らせ・文章・サービス名などの中身**→ Pages CMS で直接編集(デザイン機能は不要)

## 付録:AI検索対応(GEO)として実装済みの項目

このサイトには以下が組み込み済みです。運用で意識するのは「記事の書き方のコツ」(3章)だけで大丈夫です。

- 全ページ固有の title/description/canonical URL
- OGP・Twitterカード(SNSシェア用メタ情報)
- JSON-LD構造化データ(Organization/WebSite/Article/NewsArticle/Person/BreadcrumbList/FAQPage)
- `https://bizmote.jp/llms.txt`(AIクローラー向けサイト案内。記事を追加すると自動更新)
- `robots.txt` でAIクローラー(GPTBot/ClaudeBot/PerplexityBot等)を明示許可
- サイトマップ自動生成(`/sitemap-index.xml`)
- RSSフィード(`/rss.xml`)
- 更新日の表示と構造化データへの反映
